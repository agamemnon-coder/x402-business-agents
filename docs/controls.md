# Controls (SOC 2 style)

> **Written by Claude (an AI model) from this repository on 20 November 2026, for the maintainer. Not an audit.**
> Every status below was decided by reading the code, tests, workflows and records named in its cell, on `main` as it
> stands that day; nobody outside the project has checked it.

What Purser has in place, written the way an auditor reads controls: each control, how it works, and for each of four
questions a status with the file, test or record behind it. This replaces the version of 2 November 2026
(`build/next`), whose open points are kept below unless the code now shows otherwise. This is not a SOC 2 report: no
auditor has tested these controls, and the build runs on the Airwallex sandbox and Alta testnet only. (Alta was called
Metal until November 2026.)

The risks behind the controls: [controls-matrix.md](controls-matrix.md). The threat model: [security.md](security.md).
The ASVS self-assessment: [security/asvs-l2.md](security/asvs-l2.md). Roles in Purser Cloud:
[security/roles.md](security/roles.md). What to do when a control fires: [runbook.md](runbook.md).

**The four statuses**, each given separately:

- **Implemented**: the code or configuration is on `main`.
- **Tested**: an automated test in `test/` holds it (on stand-ins for Airwallex, Alta and Claude unless the cell says
  otherwise). CI runs the suite on every push and pull request.
- **Deployed**: it acts where test money moves today, as a committed record shows: a recorded live sandbox or testnet
  run of the runner, the hosted relay (`kit11`) or the hosted /try (`purser-try`), or GitHub for the workflows. The
  repository records no deploy of a given commit to the Workers (deploys are by hand, [cloud.md](cloud.md)), so a
  Worker change made after the last recorded deploy is "not recorded", never assumed live.
- **Independently verified**: checked by someone outside the project (an auditor, a penetration tester). **No control
  is.** The review of 20 November that [security.md](security.md#execution-re-checks-the-signature-20-november-independent-review)
  calls independent found findings 1, 2, 5 and 7; the repository records no re-check of the fixes by that reviewer.

Marks: ✅ yes, with the evidence named. 🟠 no, or only partly, with what is missing.

### What needs a person (Face ID)

 Anything beyond the limits above becomes a proposal; nothing moves until it is
approved, and the hash, expiry and passkey rules apply to every one of them:

- **Refund batches** over 0.10 a refund or 0.20 a dispute ([`refund_batch`](../src/seller/desk.ts)).
- **Mandate replacements**, which rebalance the agents' budgets within the 20.00 total
  ([`mandate_replace`](../src/agents/treasury.ts)); two people once four eyes is on.
- **Invoice payouts**, including the licence ([`invoice_payment`](../src/agents/euroBill.ts)); two people above the
  four-eyes threshold.
- **Card limit raises** ([`proposeCardRaise`](../src/agents/cardBuyer.ts), a `policy_change`; tested in
  [cards.test.ts](../test/cards.test.ts): nothing changes until it is approved and synced).
- **Policy loosening** (a higher or removed limit, a lower floor, an unblocked payee, lifting a stop, a higher limit to
  pay alone). The phone can only tighten; a loosening is proposed on the runner and approved with Face ID
  ([`loosens`](../src/policy/rules.ts); [passkey.test.ts](../test/passkey.test.ts), N2). Also:
  [`task_card`](../src/agents/askPurser.ts) above the threshold, [`payee_change`](../src/policy/payeeChange.ts) and
  [`owners_execute`](../src/metal/ownersExecute.ts) (always two owners).

### Safety

- **Idempotent money calls.** Every Airwallex write carries a request id that is stored before the call. After a timeout
  or a lost answer, Purser looks the request id up first and adopts what it finds; it never sends blind a second time
  ([src/executors/invoicePayment.ts](../src/executors/invoicePayment.ts), the `transfers` table;
  [contract/airwallex.test.ts](../test/contract/airwallex.test.ts): "a lost answer, then duplicate_request_id on the resend:
  the existing transfer is adopted, paid exactly once").
- **Audit chain.** The audit log is append-only (the database refuses updates and deletes) and hash-chained: each row
  holds the hash of the one before. `npm run verify` recomputes the chain from the genesis hash and re-checks every
  passkey approval, credential and pull; `npm run verify-log` checks an exported log
  ([src/audit/log.ts](../src/audit/log.ts), [src/cli/verify.ts](../src/cli/verify.ts); [audit.test.ts](../test/audit.test.ts)).
- **Reconciliation.** Each Airwallex transfer and card transaction and each Alta payment is checked against the ledger
  by id and amount, every hour while the runner runs; a difference is an audit row and an alarm, and nothing is fixed
  automatically (`npm run reconcile`; [reconcile.test.ts](../test/reconcile.test.ts)).
- **No secrets in the repository.** Keys come from environment variables only (Airwallex, Alta, Anthropic, T:0, the
  hub); error text is passed through [`redactSecrets`](../src/lib/redact.ts) before it is stored, and the hub's address
  and token are never logged.
- **Sandbox and testnet only.** The Airwallex client refuses any base URL but the sandbox; Alta runs on testnet. All
  money here is test money.
- **A person signs.** Face ID on the exact terms hash, re-verified before money moves; a typed hash prefix can only
  reject once a passkey is enrolled; four eyes above the CFO's threshold. Second approver: a labelled test passkey in
  this demo. In production this is a second person.
- **Outside services never decide alone.** The hub can only add a "no": unreachable, it falls back to Face ID alone,
  recorded. T:0 gets the books after a payment, in the background: a failure is logged and the payment is not affected.
