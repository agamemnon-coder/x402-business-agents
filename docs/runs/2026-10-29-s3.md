# S3 run, 2026-10-29 (Metal testnet + Airwallex sandbox, live)

`npm run s3` on the ledger from the S2 run. The Metal side (sweep `sweep-20261029-1`, 1.35 *USDZ,
finality-gated, credit locked) was done in the second session; this run is the Airwallex side.

- **Health:** the sandbox answers on the first login; it starts with 10,000,000 each in USD, EUR, GBP and
  CNY, zero in every other currency.
- **Seed:** one simulated USD deposit of 25,000.00, reference `kit11-seed-funding`, SETTLED within a second.
  Floors are calibrated from the live balances so the demo still shows a shortfall: EUR floor 500.00,
  EUR committed 9,998,000.00 (leaves 1,500.00 free), USD floor 10,020,000.00.
- **Credit:** the locked sweep credit `63825:0x9d9c1807…1f10:1` is booked as simulated deposit
  `e49d68f2-bcc2-4a0d-ab22-abca60ea6509`, USD 1.35, reference = the Metal tx hash
  ([`0x9d9c1807…1f10`](https://testnet.metalntwx.com/tx/0x9d9c1807ca44ae2b835c35c5530e0645f1ecd3622aec6d7eb5a79319998e1f10)).
  Simulated because the sandbox cannot receive stablecoins; 1 *USDZ = 1 USD.
- **Invoice:** `fixtures/lizenzhaus-invoice-LIC-2026-11.txt`, classified by Haiku, extracted by Sonnet:
  LIC-2026-11, Lizenzhaus Beispiel GmbH, EUR 1,850.00, due 2026-11-16. The IBAN matches the allowlisted
  beneficiary `1322d7e4-5102-4858-ac2f-912d0ad5b999` (DE EUR SWIFT, created in this run).
- **Plan:** EUR needed 1,862.85 (invoice + SWIFT fee 12.85), free EUR 1,500.00, so convert only the
  shortfall: buy EUR 362.85 for USD 408.62 at 1.126151, quote `101475c7-493b-3442-9734-3b2c0ce83f6f`
  (15 minutes). USD after: 10,024,592.73, above its floor.
- **Review:** Opus, advisory: approve.
- **Approval:** proposal P-0004, sha256 `985acf47…1066`, expires 05:56:40 UTC (the quote's lifetime minus
  the safety margin). Max approved it at 05:51 UTC in the Claude Code chat; Claude typed the hash prefix
  (audit approver `max (via chat with Claude)`). Claude's own attempt to approve was blocked: payments wait for a person.
- **Conversion:** `e2b5a849-0567-4a2f-9fc5-701349d2d0b8` on the approved quote, EUR 362.85 for USD 408.62, SETTLED.
- **Transfer:** SWIFT `26954165-5c6d-4796-91bd-c9aa356e1ea9`, EUR 1,850.00 to Lizenzhaus, metadata
  `approval_sha256 = 985acf47…1066`, simulated SENT then PAID. `npm run verify`: all checks pass.
- **Finding:** Airwallex charged a fee of **EUR 13.47**, not the 12.85 the plan assumed, so free EUR ended at
  -0.62: the payment touched 0.62 of committed money. Fixed after this run: the plan now reserves a fee ceiling
  of EUR 20.00 (`fee_max` in the approved terms), and the executor records the real fee and flags one above it.

## Open items from build plan 1.6, answered

| # | Question | Answer from the live sandbox |
|---|---|---|
| 4 | Does a simulated deposit's `reference` come back in `GET /deposits`? | Yes, verbatim (both the seed reference and the 66-character tx hash). |
| 5 | Starting balances | 10,000,000 in USD, EUR, GBP and CNY; 0 elsewhere. |
| 8 | Do `PENDING` simulated deposits show in `pending_amount`? | Not observable: simulated deposits settle within about a second (`SETTLED`). |
| 11 | Can conversions be looked up by `request_id`? | Yes: `GET /fx/conversions?request_id=…` returns exactly the one conversion, and none for an unknown id. |
| 6 | Default API version | Transfers use the newer vocabulary (`transfer_amount`, `amount_beneficiary_receives`, status `PAID`); the exact version string is not exposed. |
| 7, 12 | `expired_quote`, PAID → FAILED | Still open: the F-scenarios test these. |

## Quirks seen

- `GET /deposits` wants `page_num` and `page_size` together (the adapter already sends both).
- `GET /fx/conversions` rejects `page_size` below 10.
