## What was wrong, and the fix

1. **`/` without a viewer key** showed empty panels with zeros and polled `/api/snapshot`, getting 401 each time.
   - A guest now sees a landing: the one-line pitch, **Watch the demo** and **A month in 90 seconds**.
   - The page asks the relay for nothing without a key.
   - A viewer link that stops working stops the polling.
   - Screenshot: `docs/screens/guest-home-phone.png`.
2. **`/demo` printed "null".** `replaceChildren()` got a null child (a step without an approval) and printed it as
   text.
   - Null children are filtered out now.
   - The jury review also found that the approval banner shared its class name with the step card's tone. That
     squeezed the Face ID steps into columns on a phone. It is renamed.
3. **Order and words.**
   - The story now opens with the company card: approved, declined over the limit, raised with Face ID, approved.
     Then come the per-request payments on Metal.
   - Each step's text is in plain words. The technique ("x402", "EUR/USD tick", "mandate_cap_exceeded") sits under
     **How it works**.
   - The tabs say what each step is.
   - Amounts are written with thousands separators.
   - Screenshots: `docs/screens/demo-step1-laptop.png`, `docs/screens/demo-step1-phone-dark.png`.
4. **Header:** the six lines about testnet and sandbox are one line, "Test money, real systems", with details on tap.
5. **Judge mode:** `npm ci && npm run judge` serves the recorded run and the month on localhost and opens the
   browser. It needs no keys and no ledger. `--check` fetches each page and exits, for CI.
6. **The page check above** runs in CI.

`npm test`: 343 tests pass, including new tests that the recorded story never shows null, undefined or NaN, opens
