## What the first run found, and the fixes

The first run of the day gave 2 failures in `verify-all` and 9 in the link check. None was a wrong claim or a dead
page a judge would open:

- **`verify-all`, 2 checks.** The /proof page shows "233 Alta testnet transactions, all runs" and "451 Claude calls
  with request ids, all runs and evals". The figures match the records; the check looked for the label without the
  scope after the comma. It now matches the label itself (`src/cli/verifyAll.ts`).
- **Links, 2 live pages reported dead.** developer.visa.com answers HEAD with 404 for a page that GET serves (200); the
  check now asks with GET after a 404 too. One Cybersource docs page answered 404 once and 200 on the next run.
- **Links, 6 API endpoints.** Cybersource's API hosts, the Airwallex sandbox API and Purser's MCP endpoint are named in
  the docs as endpoints a program calls, not pages; a bare request gets 403, 404 or 405. The check now reports them as
  endpoints (up when they answer at all), and still fails one that does not answer.
- **Links, 1 truly gone.** A build file of Cybersource's API reference (`main.BVga27j8.js`, read 12 November) is no
  longer served; the page now loads a newer build. `docs/visa-icc.md` links the page that loads it and keeps the old
  file name with the date it was read.
