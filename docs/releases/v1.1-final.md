# v1.1-final (draft notes; the tag is the owner's to create after the final merge)

The release after `v1.0-submission` (8 November 2026): 100 pull requests merged into main, listed one by one in
[CHANGELOG.md](../../CHANGELOG.md) (generated from git). Test money only throughout: the Airwallex sandbox and Metal
testnet. Every run below has a dated record; what was simulated is said in each.

## New live runs (records in docs/runs/)

- **Metal, the passkey account on chain** (12 Nov): two owners, the CFO's passkey and a labelled virtual test passkey,
  signed 2 of 2 to bind, raise and revoke an agent's mandate; Metal refused a payment over the cap on chain.
  [Record](../runs/2026-11-12-faceid-onchain.md).
- **Airwallex, two locks on one payout** (10 and 12 Nov): signed in Purser by a labelled virtual test passkey, held
  `IN_APPROVAL` by Airwallex's own workflow until a person approved it there, then PAID with simulated settlement.
  [Record](../runs/2026-11-12-airwallex-two-locks-paid.md).
- **Invoice token on Metal testnet** (12 Nov): minted, financed and settled; a prototype with a simulated financier.
  [Record](../runs/2026-11-12-tokenize.md).
- **Moneybird** (12 Nov): a test company's purchase books in a Moneybird sandbox administration, read back with 0
  differences. [Record](../runs/2026-11-12-moneybird-sandbox.md).
- **T:0** (10 Nov): the main run's books posted as journal entries to T:0's shared sandbox entity.
  [Record](../runs/2026-11-10-t0-journal-sandbox.md).
- **Airwallex connected accounts** (10 Nov): three test companies, payouts with Purser's fee.
  [Record](../runs/2026-11-10-platform-e2e.md).
- **Visa Intelligent Commerce via Airi** (12 Nov). [Record](../runs/2026-11-12-vic-3.md).
- **The CFO's real Face ID at Airwallex** (13 Nov): the owner's own iPhone approved an invoice, Purser created the SWIFT
  transfer once and Airwallex held it `IN_APPROVAL`; the step to PAID was not done that day.
  [Record](../runs/2026-11-13-airwallex-faceid.md).
- **Visa via Airwallex's Airi, fourth run** (13 Nov, sandbox, test card): 2 paid (1 after Face ID), 5 refused by Purser incl.
  reused credentials, 1 not tapped: nothing charged. [Record](../runs/2026-11-13-vic-4.md).
- **A month of books** (13 Nov): a test company's 20 supplier invoices read and coded by Claude, 16 paid on the
  simulated bank, the books balanced. [Record](../runs/2026-11-13-books-month.json).
- **Try with Claude** (13 Nov): one visit of the hands-on demo, Claude Haiku reading the invoice, a simulated bank and
  a test passkey. [Record](../runs/2026-11-13-try-sample.json).

Every run, newest first: [docs/runs/README.md](../runs/README.md).

## How to create it (owner)

```sh
git fetch origin && git checkout <the final merge commit on main>
git tag -a v1.1-final -m "v1.1-final"
git push origin v1.1-final
```

Then a GitHub release from that tag, with these notes. The existing `v1.0-submission` tag is not moved.
